# DeepMoji Feasibility Check

Ethan asked in the 11/10 meeting whether DeepMoji can be connected to MELD and our RoBERTa model without conflicts. This folder answers that before Milestone 3. It is a **feasibility check, not an experiment**: no condition from `experiment_plan.md` has been trained, and none of the numbers below say whether DeepMoji improves RoBERTa.

**Answer: yes, it connects.**
- torchMoji, the PyTorch port of DeepMoji, runs alongside our pinned `torch==2.14.1` / `transformers==5.22.1` after three small fixes to old code. After the fixes it reproduces its own reference outputs exactly.
- Features extract for all 13,708 MELD utterances in about 7 seconds on CPU.
- The concatenation path in `strong_baseline/model.py` runs end to end.

All results below were produced on 2026-11-15 on a Windows laptop (CPU, Python 3.13).

## How to run

From the repository root, in an environment with `strong_baseline/requirements.txt` installed:

```bash
pip install -r deepmoji/requirements.txt
python -m deepmoji.setup_torchmoji      # clone pinned torchMoji, apply fixes, download + verify 85 MB weights
python -m deepmoji.check_torchmoji      # reference outputs, shape, determinism, freezing, random control
python -m deepmoji.extract_features     # features/deepmoji/pretrained/{train,dev,test}.npy + unknown-word stats
python -m deepmoji.probe                # output/deepmoji-probe/{dev,test}.jsonl
python score.py --gold data/processed/test.jsonl --pred output/deepmoji-probe/test.jsonl
python -m deepmoji.fusion_smoke         # RoBERTa-base + DeepMoji, 64 utterances, about 1 minute on CPU
```

Notes:
- **Random-weight control.** For conditions R / CR in `experiment_plan.md`, run `python -m deepmoji.extract_features --random-seed 13` once per training seed.
- **What is not committed.** `third_party/` (the patched torchMoji checkout and weights) and `features/` are git-ignored. Both are regenerated by the commands above. torchMoji is not pip-installed; `deepmoji/common.py` adds `third_party/torchMoji` to the import path.
- **On Colab.** Run the same commands after the strong baseline's setup cell.

## The three fixes to torchMoji

torchMoji is pinned to commit `9dd01df` of https://github.com/huggingface/torchMoji (MIT license). That commit predates Python 3.11 and PyTorch 1.1. `deepmoji/setup_torchmoji.py` applies each fix as an exact text replacement and stops if the original text is not found. Each fix restores the original behaviour:

| File | Problem on current versions | Fix |
|---|---|---|
| `tokenizer.py` | `(?i)` in the middle of a regex is an error since Python 3.11 | Remove it. Compile the whole pattern with `IGNORECASE`, which is what old Python did with a mid-pattern flag |
| `lstm.py` | `PackedSequence` has 4 fields since PyTorch 1.1, so `input, batch_sizes = input` fails | Read `.data` and `.batch_sizes` |
| `filter_utils.py`, `word_generator.py` | `word.decode('ascii')` raises `AttributeError` on a Python 3 `str`, so the "is it ASCII?" check always fails | `word.encode('ascii')` |

The last fix matters most because the bug is **silent**. Nothing crashes, but without the fix `shorten_word` never shortens 3+ repeated characters. So "!!!", "..." and "Ewww" are not mapped to their in-vocabulary forms "!!", ".." and "eww", and they become unknown words. On MELD this raises the unknown-token rate from 1.49% to 2.07% and changes the features. Anyone using torchMoji on Python 3 should apply it.

`check_torchmoji` reproduces both numeric checks from torchMoji's own `tests/test_finetuning.py`: the top-5 emojis for seven sentences, and the mean of the first five feature dimensions.

## Results

### Checks (`check_torchmoji`)

All nine checks pass:
- reference emoji top-5 and feature mean;
- shape `(n, 2304)`;
- finite values;
- identical output on a second pass;
- no parameter requires a gradient;
- random control: shape, same seed gives identical features, and different seeds differ.

### Feature extraction (`extract_features`)

| Split | Utterances | Shape | Longest (DeepMoji tokens) | Time (CPU) |
|---|---|---|---|---|
| train | 9,989 | 9,989 × 2304 | 87 | 5.1 s |
| dev | 1,109 | 1,109 × 2304 | 45 | 0.6 s |
| test | 2,610 | 2,610 × 2304 | 53 | 1.3 s |

- Nothing is truncated: the length limit is 200 tokens.
- DeepMoji receives the utterance text only, without the `Speaker:` prefix (`experiment_plan.md`).
- Row order is saved next to each matrix (`<split>_ids.json`) and checked against `data/processed` wherever the features are read.
- Two extractions on the same machine are bit-identical.

### Unknown words (Ethan's question)

Unknown means mapped to `CUSTOM_UNKNOWN` in the 50,000-word DeepMoji vocabulary. Rates are measured over all three splits (140,773 tokens).

| Text given to DeepMoji | Unknown tokens | Utterances with ≥ 1 unknown | Most frequent unknowns |
|---|---|---|---|
| Raw MELD text | 1.49% | 12.7% | i-i 168, no-no 113, pheebs 91, you-you 40, and-and 38, uh-huh 33 |
| Curly quotes → straight | 1.49% | 12.7% | identical: torchMoji already maps `’` to `'` internally |
| Hyphens between letters split | 0.73% | 6.6% | pheebs 91, geller 29, chandler's 19, tribbiani 15, gunther 11 |

- **Curly quotes.** The curly apostrophe (4,966 occurrences in MELD) makes no difference, so it needs no cleaning.
- **What is left.** Two groups remain: stuttered hyphenated words ("i-i", "no-no", "uh-oh") and character names.
- **Splitting hyphens.** Splitting hyphens between letters halves the unknown rate, and afterwards almost everything left is a name. Whether to apply this to DeepMoji's input is a decision for M3. If we do, it changes only DeepMoji's input, not RoBERTa's, and it must be the same in every DeepMoji condition. The features above use the raw text.

Full counts are in `features/deepmoji/pretrained/unknown_words.json` after extraction.

### DeepMoji features alone carry emotion information (`probe`)

The probe is a logistic regression on standardised DeepMoji features (statistics from train), with no RoBERTa. All scores come from `score.py`.

| System | Dev W-F1 / M-F1 | Test W-F1 / M-F1 | Test excl. overlap W-F1 / M-F1 |
|---|---|---|---|
| Majority class | 25.23 / 8.50 | 31.27 / 9.28 | 31.45 / 9.30 |
| **DeepMoji probe** | **46.96 / 33.92** | **49.36 / 33.96** | **49.48 / 34.05** |
| RoBERTa-base (5 seeds) | 59.57 / 43.67 | 63.33 / 44.82 | 63.34 / 44.81 |

- **The features carry information.** The probe is far above the majority baseline, so the frozen features contain emotion information. It is well below RoBERTa, as expected for a linear model on frozen features.
- **Rare classes.** On test the probe reaches fear F1 11.97 and disgust F1 19.85. Both fall within RoBERTa's ranges across seeds (3.6–21.4 and 12.2–26.4).
- **What this does not show.** It hints that DeepMoji captures something about the rare classes, but it does not show that concatenation will help.
- **Sensitivity.** Rerunning the probe on the same features gives identical predictions. An earlier ad-hoc extraction differed by at most 2.4e-7 per value (float32 rounding), and that alone moved macro F1 by up to 0.5. Treat probe scores as ±0.5, and expect similar float-level differences on other hardware.

### Concatenation runs end to end (`fusion_smoke`)

The smoke test uses the strong baseline's own `Encoded`, `make_collate`, `UtteranceClassifier(aux_dim=2304)` and `evaluate`, unchanged. It trains on the first 64 train utterances for one epoch (4 steps), then predicts and scores the first 64 dev utterances.

What it confirms:
- The classifier is 7 × 3072, made of 768 `<s>` dimensions and 2304 DeepMoji dimensions.
- The loss is finite, and gradients reach both parts of the classifier and the RoBERTa encoder.
- Prediction and `score.py` work.
- The model rejects missing `aux_features`.

`train.py` does not read features yet. Adding that is Milestone 3 work.

## Points to settle for Milestone 3

1. **Outliers after standardising.** No DeepMoji dimension is constant on train, but the smallest standard deviation is 3.2e-4. After standardising with train statistics, a few dev/test values reach |z| ≈ 75 (0.05% of values have |z| > 10). Consider a floor on the standard deviation or clipping z-scores, and apply the same rule in the pretrained and random conditions.
2. **Scale of the two parts.** In the smoke test, the classifier gradient on the standardised DeepMoji part is about 2–3 times that on the `<s>` part. The two parts are on different scales, so the DeepMoji part may dominate the head early in training. Check this before the full runs, for example by comparing their norms or adding a LayerNorm per part. The same choice must apply to the random control.
3. **Hyphen splitting** for DeepMoji's input (see above).
4. **Random control.** Use one `--random-seed` per training seed, as `experiment_plan.md` specifies.
